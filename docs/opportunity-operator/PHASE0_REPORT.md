## 3. Security boundaries demonstrated

| Boundary | Demonstrated by | Not demonstrated |
|---|---|---|
| The agent cannot approve, submit, accept, certify, pay or mark prerequisites done | No such code path exists (architecture scans); DB triggers + authorizer reject every forged or borrowed attempt (matrix, randomized walk) | A process that opens the SQLite file with its own code (shared OS user) can still alter it; startup verification detects dropped/edited guards but cannot prevent them |
| Owner decisions are single-use, typed, and atomic | Decision-reuse and rollback tests; CLI refuses without a TTY | Owner identity is "whoever has local terminal access" |
| Restricted material cannot be stored, ingested or read | `RESTRICTED` rejected by schema; no ingest command/setting; data dir refused inside any git worktree or forbidden root; symlinks refused; a hostile page and a hostile model told to read a synthetic restricted repo produced zero opens/listings of it and no process/socket events (audit hook) | An OS-level boundary: the agent process still runs with your user's file permissions. Container or separate-OS-user isolation is a Phase 3 item |
| Profile data reaches a model only through `ContextBuilder` | Matrix tests; canary sweep; AST test that models/search/network are reached only inside guarded wrappers and prompts can be minted only by the builder; sensitive and unverified facts never leave | A caller in the same process can still reach private attributes such as `app.llm._inner`; Python cannot prevent that |
| Deny-list tripwire | Variant/leetspeak/separator/URL-encoded matching; blocks query, prompt, API body, URL, model output; incident stores only a hash | Paraphrase, translation or encoding tricks can evade any text filter; it is a backstop only |
| Every fact traces to a source and a checked quote | Quote check with offsets; re-verification audit; tampered snapshot detected; scoring excludes unverified evidence | The DB cannot read files, so a lying writer can insert `quote_verified=1`; the audit catches it afterward (tested) |
| Network is read-only, public-only, credential-free | 45 fetch-policy tests with a mock transport | **DNS rebinding:** in `direct` mode the address is validated before the request but the connection resolves again; pinning the validated address is not implemented. The only live check was in `proxy` mode, where the proxy decides |
| Real prompt-injection resistance | Hostile page + hostile model simulated with mocks | No real model has been tested yet; adversarial fixtures against the real model come with Phase 1 |
